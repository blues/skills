# Prepare and improve Project Q&A

Use this when the user wants to get ready for useful questions, a question recurs, or an
answer is slow to calculate. Reuse Access, Project Selection, product knowledge and any
Cloud Computer setup already completed. Prepare only useful calculations; ordinary
questions can go straight through the question procedure.

## 1. Choose the questions worth preparing

Start with the user's pending question, recurring questions and useful examples supported
by the loaded product knowledge. Include native platform questions where relevant. For a
broad readiness request, choose a small representative set, such as current state and a
period or population comparison; do not enumerate every possible question.

Find existing plans with the same quantity, population, time basis and validity rules.
Reuse those whose meaning still holds. Missing product meaning limits the affected
question, not all Q&A.

## 2. Prepare or repair the calculation

Reuse the source-selection and verification rules from the question procedure. A plan
stores how to calculate an answer; each execution needs suitable current evidence.

| What is needed | Procedure | Result |
|---|---|---|
| Answer the current question or choose sufficient evidence | [Answer a question](https://raw.githubusercontent.com/blues/skills/refs/heads/master/notehub-project-chat/querying.md) | A verified answer from the cache, enabled MCP Repository or Notehub API |
| Save or improve a calculation for repeated use | [Prepare a reusable question](https://raw.githubusercontent.com/blues/skills/refs/heads/master/notehub-project-chat/prepared-questions.md) | A parameterized calculation with meaning, coverage requirements and checks |

On a Cloud Computer, use the existing cache and private plan records. In a foreground
session, reuse knowledge and calculations within the available session; temporary analysis
files do not create an ongoing cache or monitor. If evidence is missing, use another
suitable source or state the limitation. Supported questions can proceed while history fills.

## 3. Improve the measured bottleneck

Filter and aggregate near the data, select needed fields, and batch compatible reads.
Reuse verified typed projections when they help; do not rebuild the cache for each question.
Measure where time is spent before changing a working calculation or storage layout.

| Observed problem | Procedure | Result |
|---|---|---|
| Repeated JSON extraction or slow local scans | [Query performance](https://raw.githubusercontent.com/blues/skills/refs/heads/master/notehub-cloud-agent/query-performance.md) | Record actual field usage and compare the results and cost of a useful optimization |
| A failed shared maintenance task leaves evidence stale | [Maintenance task](https://raw.githubusercontent.com/blues/skills/refs/heads/master/notehub-cloud-agent/cache-maintenance.md) | Repair the failed component while preserving enrollment, checkpoints and pauses |

Cloud maintenance owns schema refresh, retention and physical optimization. Q&A supplies
actual fields, query plans and timings for that review. A field's presence in a schema is
not by itself a reason to index it. A faster query does not compensate for stale inputs.

## 4. Verify and return to Chat

Check that an improved plan preserves the intended answer, units, population and coverage.
When product meaning or schema changes, recheck affected calculations and preserve working
plans that remain valid. Reuse an existing verification while its assumptions hold.

Return the pending answer, or a short readiness report with grounded example questions,
to the Chat loop. Retain the calculation and relevant checks privately for follow-ups.
Chat owns recognizing interests and turning useful questions into monitors.
